## SAML trust and login result

`SAML2.WebSSO.API.parseAuthnResponseBody` leniently decodes Base64, parses outer response/issuer and assertions, requires consistent outer/assertion issuer and looks up admin-configured IdP with optional team. Trust comes from that IdP's stored signing certs, never arbitrary response KeyInfo. Each top-level assertion must have ID and pass verification; only verified returned subtrees are judged. XML Signature requires unique matching ID/reference target, child signature, valid digest/transforms/canonicalized SignedInfo/key signature. Same-document #ID references only; unsupported reference forms fail. Source verification accepts exactly one successful configured credential (not simply any count). RSA-SHA1 and RSA-SHA256 verifier branches, supported digest/canonicalization/transform algorithms and ADFS whitespace workaround remain actual source formats; do not infer capabilities from unused library branches. Expired signing certs are intentionally accepted; independent configured SHA1 fingerprint allowlist applies to all descriptor/login certs and empty disables it.

`SP.judge1`: assertion's InResponseTo resolves persisted request issuer, rejecting missing/unknown/wrong issuer; validate assertion IssueInstant, persistent assertion replay ID/lifetime, conditions NotBefore/NotOnOrAfter/audience, bearer subject confirmations/recipient/times, authentication statement/instant/session expiry. Source consumes request after judgement reaches checkAssertion. Multiple assertions must produce one distinct identical granted user reference with no denied assertion; mixed/conflicting grants fail. Respect source clock comparison/tolerance rather than library defaults. Signed assertion drives recipient/request/time, not unsigned envelope fields; envelope non-success status still denies. Missing InResponseTo follows source303 to initiation, not direct unsolicited authentication.

`Spar.App` performs account/team/SSO/provisioning/NameID/IdP replacement/migration/binding decisions and calls Brig for persistent cookie. Source lowercased case-fold identity mapping ignores NameID qualifiers in normalized lookup; preserve full user ref serialization and current user_v2 scoping. Deleted native account can be recreated on later authorized SAML login according to original policy. Never create a local successful session without actual Brig effect.

Web granted/denied/error results use source XHTML template/status200, text/html;charset=utf-8 and AUTH_SUCCESS/AUTH_ERROR postMessage to '*'; grant forwards actual Brig Set-Cookie, failure doesn't invent one.
